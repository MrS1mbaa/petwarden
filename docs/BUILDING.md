# Building an APK

> **Supported setup.** Builds are tested on Windows 11 with the versions below. Other operating systems, newer SDKs or modified sources may need changes on your side; build problems with other setups are not treated as bugs (see [CONTRIBUTING.md](../CONTRIBUTING.md)).

## Requirements

- Node.js 22.13+ and npm
- JDK 17 or newer (Android Studio's bundled JBR works)
- Android SDK with Platform 36 and Build-Tools 36.0.0

## Local build (Windows)

```bash
npm ci
```

Then double-click **`Build-APK.bat`**, or run it from a terminal. It finds the JDK and Android SDK, runs `expo prebuild` and Gradle `assembleRelease`, copies the result to `build-apk/PetWarden-local-<date>.apk`, prints the SHA-256 and opens the folder.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-apk.ps1 -CheckOnly   # verify JDK/SDK only
powershell -ExecutionPolicy Bypass -File scripts/build-apk.ps1 -NoOpen      # do not open Explorer
```

The first build downloads Gradle and Maven dependencies (about 10 minutes); later builds take about a minute.

**If the native build cannot find Skia libraries** (newer npm versions may skip install scripts and print `install-scripts ... not yet covered by allowScripts`), run once:

```bash
node node_modules/@shopify/react-native-skia/scripts/install-libs.js
```

The `android/` folder is generated by `expo prebuild` and git-ignored. Never edit it by hand; change `app.json` or a config plugin instead.

## Signing

`plugins/withReleaseSigning.js` signs release builds with a key read from `~/.petwarden/keystore.properties`:

```properties
storeFile=C:/Users/you/.petwarden/release.jks
storePassword=...
keyAlias=petwarden
keyPassword=...
```

Without that file the build falls back to the debug key. The keystore and its properties stay outside the repository (`*.jks` is git-ignored). An APK signed with one key cannot be installed over one signed with another; uninstall first.

Create a key with:

```bash
keytool -genkeypair -v -keystore release.jks -alias petwarden -keyalg RSA -keysize 2048 -validity 10000
```

## Installing on a phone

```bash
adb install -r build-apk/PetWarden-local-<date>.apk
```

Wireless: enable *Developer options → Wireless debugging*, then `adb pair <ip:port>` once and `adb connect <ip:port>`.

## EAS (cloud) builds

`eas.json` defines `preview` (APK) and `production` (AAB) profiles:

```bash
npx eas-cli@latest build --platform android --profile preview
```

## Permissions

`app.json` blocks `INTERNET`, `ACCESS_NETWORK_STATE`, `SYSTEM_ALERT_WINDOW`, the push-token permission and Google Play's install-referrer permission: the app never touches the network. `plugins/withoutFirebase.js` removes the Firebase and Google Play services components that `expo-notifications` merges into the manifest (push messaging, Firebase init, Google's log transport); only local notifications are used. It adds `USE_EXACT_ALARM` so reminders fire on time. Google Play restricts that permission to alarm and calendar apps; for a store release either justify it in the declaration form or switch to `SCHEDULE_EXACT_ALARM`.

## License notices

`licenses/npm.json` and `licenses/android.json` hold the license text of every third-party package and Android library. After changing dependencies, regenerate them (the Android part needs a finished local build, because it reads the Gradle dependency tree and cache):

```bash
npm run licenses
```

`npm run check` (and CI) fails when `licenses/npm.json` no longer matches `package-lock.json`. Rerun `npm run licenses` and commit both files.

## Expo CLI telemetry

The Expo command-line tools send anonymous usage data from the developer's computer (not from the app). To turn that off on your machine, set `EXPO_NO_TELEMETRY=1` before running `npx expo` commands.
